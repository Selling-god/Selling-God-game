## 아득한 길의 서약 · THE UNWRITTEN ATLAS

실시간 온라인 도트 액션 RPG의 **전직 이야기·대륙 확장 업데이트**입니다.

## 2. 내 컴퓨터에서 먼저 실행하기

### 준비
- Node.js **22 계열의 22.12 이상 버전**이 필요합니다. 테스트 런타임은 22.16.0이었습니다.
- 최초 의존성 설치에는 인터넷이 필요합니다.
- 게임 실행에 Python은 필요하지 않습니다. Python은 그림 재생성과 선택적 브라우저 테스트용입니다.

### Windows
압축을 풀고 `START_LOCAL.bat`을 실행하세요. 설치·빌드 후 주소를 안내합니다.
브라우저에서 `http://localhost:3000`에 접속합니다.

### 직접 명령어로 실행
프로젝트 폴더에서 아래 순서대로 실행합니다.

```bash
npm ci
npm run build
```

`.env.example`을 `.env`로 복사하고, 기본값을 유지한 뒤 실행합니다.

```bash
npm start
```

macOS/Linux에서는 `sh start-local.sh`로도 같은 절차를 실행할 수 있습니다.

로컬 개발 모드에서는 `.local-data` 폴더에 저장됩니다.
브라우저의 개발 계정 ID와 이 폴더를 보존해야 같은 캐릭터를 이어 할 수 있습니다.
일반 창과 시크릿 창을 각각 열면 두 명 접속을 시험할 수 있습니다.

**로컬 개발 저장은 Render 운영 저장 방식이 아닙니다.**
개발 모드는 명시적으로 허용한 개발 환경의 루프백 접속에서만 작동하며,
`NODE_ENV=production`에서는 `ALLOW_DEV_GUEST=true`를 넣어도 거부합니다.
외부 사용자를 접속시키려면 아래 Supabase 배포 설정을 하세요.

## 3. Supabase 무료 프로젝트 설정

### A. 프로젝트 만들기와 테이블 생성
1. Supabase에서 새 프로젝트를 만듭니다.
2. 프로젝트의 **SQL Editor → New query**를 엽니다.
3. 이 ZIP의 **`supabase/setup.sql` 전체 내용**을 붙여넣고 실행합니다.
4. 마지막 확인 결과의 `relrowsecurity`가 `true`인지 확인합니다.

이 SQL은 `starfall_characters` 테이블과 닉네임 고유 인덱스를 만듭니다.
`anon`, `authenticated`의 테이블 권한을 제거하고 서버의 `service_role`만 읽고 쓰게 합니다.
플레이어가 브라우저에서 골드나 레벨을 직접 수정하는 구조가 아닙니다.
기존 테이블을 삭제하거나 사용자 저장 데이터를 지우는 SQL은 포함하지 않았습니다.

### B. 인증 설정
Supabase Authentication 설정에서 다음을 확인합니다. 대시보드 메뉴 이름은 바뀔 수 있습니다.

- **Anonymous Sign-Ins 활성화**: 로그인 화면 없이 `모험 시작`을 누르는 빠른 시작에 필요합니다.
- 이메일 로그인 사용: 이메일/비밀번호 Provider를 활성화합니다.
- 익명 계정을 이메일로 연결하려면 **Manual Linking 활성화**가 필요합니다.
- **Site URL / Redirect URLs**: 배포가 끝난 뒤 실제 Render 게임 주소를 정확히 등록합니다.
  예: `https://내-서비스명.onrender.com` 및 필요한 경우 같은 주소의 `/` 포함 형태.
- 로컬에서 온라인 인증까지 시험할 때에만 `http://localhost:3000`을 추가합니다.

**빠른 시작 계정은 브라우저 데이터를 지우거나 로그아웃하거나 다른 기기로 이동하면 다시 접근하지 못할 수 있습니다.**
중요한 캐릭터는 게임 내 설정 → 계정 연결에서 이메일을 연결한 뒤,
이메일 인증을 마치고 비밀번호를 설정하세요. 기존 익명 캐릭터의 계정 ID가 유지되는 방식입니다.

### C. 이메일 발송에 관한 중요한 제한
Supabase 기본 이메일 발송 서비스는 일반 사용자를 대상으로 한 운영용 발송 서비스가 아닙니다.
현재 공식 문서상 기본 서비스는 프로젝트 팀에 속한 사전 승인 이메일만 대상으로 하며,
엄격한 발송 제한도 있습니다.

따라서 지인에게 실제 이메일 회원가입·비밀번호 찾기·익명 계정 연결을 제공하려면
**Supabase의 Custom SMTP 설정**이 필요합니다.
메일 서비스의 별도 이용 조건·비용·무료 한도는 운영자가 확인해야 합니다.
SMTP 없이도 Anonymous Sign-Ins로 같은 브라우저에서 게임을 시험할 수 있습니다.
이메일 확인을 꺼서 문제를 우회하는 방식은 권장하지 않습니다.

이 버전의 인증 UI에는 CAPTCHA 위젯 연동이 없습니다.
Supabase에서 CAPTCHA를 필수로 켜면 인증이 실패할 수 있습니다.
봇이 접근하는 불특정 다수 대상 공개 운영 전에는 CAPTCHA 연동·추가 가입 제한을 구현해야 합니다.
초기에는 제한된 테스트 그룹과 사용하세요.

### D. 키 준비
프로젝트 URL과 다음 두 종류의 키를 준비합니다.

| Render 환경변수 | 넣을 값 | 브라우저 공개 여부 |
|---|---|---|
| `SUPABASE_URL` | `https://프로젝트참조.supabase.co` | 공개 가능 |
| `SUPABASE_ANON_KEY` | publishable 키 또는 legacy `anon` 키 | 공개 가능 |
| `SUPABASE_SERVICE_ROLE_KEY` | secret 키 또는 legacy `service_role` 키 | **서버 전용 비밀키** |

새 키 체계도 위 환경변수 이름에 그대로 넣으면 됩니다.
`SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SECRET_KEY` 별칭도 지원합니다.
publishable/secret을 JWT `Authorization`으로 잘못 전달하지 않도록 구현했습니다.

**서비스 롤/secret 키를 `public`, `client`, GitHub, 스크린샷, 채팅에 넣지 마세요.**
실수로 서버 비밀키를 공개키 칸에 넣은 경우 시작 단계에서 감지 가능한 키 형식을 차단합니다.
키를 공개했다면 파일만 지우는 것으로 끝내지 말고 Supabase에서 키를 교체하세요.

## 4. GitHub에 업로드

압축을 푼 `starfall-online` 폴더의 **내용물**을 저장소 최상위에 올립니다.

정상 구조:
```text
저장소 최상위/
  package.json
  package-lock.json
  render.yaml
  server/
  client/
  shared/
  public/
  supabase/
  ...
```

`package.json`이 한 단계 안쪽에 있으면 Render의 Root Directory를 그 폴더명으로 설정해야 합니다.
새 비공개 저장소를 만들고 GitHub Desktop으로 폴더를 추가하거나,
웹의 Add file → Upload files로 올려도 됩니다.
실제 `.env`, `.local-data`, `node_modules`, 테스트 계정 파일은 올리지 않습니다.
`.env.example`은 비밀값이 비어 있으므로 올려도 됩니다.

GitHub Pages는 이 게임의 서버를 실행할 수 없습니다.
GitHub는 코드 저장소이고, Node 서버와 게임 페이지는 Render가 제공합니다.

## 5. Render 무료 Web Service 배포

### 권장: 직접 Web Service 만들기
1. Render에서 **New → Web Service**를 선택합니다. **Static Site가 아닙니다.**
2. 방금 만든 GitHub 저장소를 연결합니다.
3. 아래 값을 지정합니다.

| 설정 | 값 |
|---|---|
| Runtime | Node |
| Region | Supabase와 가까운 곳. Blueprint 기본값은 Singapore |
| Root Directory | `package.json`이 저장소 최상위라면 비움 |
| Build Command | `npm ci && npm run build` |
| Start Command | `npm start` |
| Instance Type | Free |
| Health Check Path | `/health` |

4. Environment에 다음 값을 등록합니다.

```text
NODE_ENV=production
NODE_VERSION=22
ALLOW_DEV_GUEST=false
SUPABASE_URL=프로젝트 URL
SUPABASE_ANON_KEY=공개 publishable 또는 anon 키
SUPABASE_SERVICE_ROLE_KEY=서버 secret 또는 service_role 키
MAX_PLAYERS=24
SNAPSHOT_HZ=10
WS_COMPRESSION=true
```

`PORT`는 Render가 제공하므로 운영 배포에서 직접 지정하지 않아도 됩니다.
`PUBLIC_ORIGIN`은 기본 onrender.com 주소를 쓸 때 비워도 됩니다.
커스텀 도메인을 쓰면 `https://game.example.com`처럼 실제 접속 origin을 넣습니다.
한 origin만 허용하므로 커스텀 도메인 설정 이후에는 그 주소로 접속하세요.

5. Deploy를 실행합니다.
6. 배포 주소를 Supabase Site URL과 Redirect URLs에 등록합니다.
7. 게임 주소에 접속해서 새 캐릭터를 만들고, 다른 브라우저로 두 번째 캐릭터를 만듭니다.
8. `/health`에서 `"ready":true`, `"persistence":"supabase"`를 확인합니다.

Blueprint 사용자는 포함된 `render.yaml`을 이용할 수 있습니다.
단, Blueprint로 만들어도 비밀키 입력과 Supabase SQL/Auth 설정은 직접 해야 합니다.

### 배포 후 읽기 전용 점검 명령
```bash
npm run check:deploy -- https://내-서비스명.onrender.com
```
서버 상태, 공개 설정, 서버의 DB 읽기 경로를 확인합니다.
이 명령이 성공해도 실제 회원가입·메일 발송·저장·다중 접속까지 자동으로 검증한 것은 아닙니다.

### 반드시 해볼 배포 승인 테스트
- 일반 창/시크릿 창 두 개로 서로 다른 캐릭터를 만든다.
- 파티 초대와 지역 채팅이 양쪽에 보이는지 확인한다.
- 같은 몬스터를 함께 때리고 체력·보상을 확인한다.
- 의뢰를 받고 물약을 구입한 뒤 설정의 저장 버튼을 누른다.
- 새로고침 또는 재접속 후 이름·장비·골드·의뢰가 유지되는지 확인한다.
- Supabase Table Editor에서 해당 계정의 저장 행을 확인한다.
- SMTP 설정 후 별도 테스트 이메일로 인증·계정 연결·비밀번호 찾기를 확인한다.
- Render 로그와 무료 사용량 대시보드를 확인한다.

| 귀환 | H. 전투가 끝나고 5초가 지나야 사용 가능 |
| 가방·의뢰·지도·파티 | I / J / M / P |
| 전직 이야기 / 직업 / 능력치 | V / C / U |
| 직업·월드 보스·탐험 수첩·능력치 | C / B / N / U |
| 적 순환 선택 | Tab |
| 기본 공격 자동 반복 | T. 이동이나 파밍을 자동화하지는 않음 |
| 채팅 | Enter |
| 설정·창 닫기 | Esc |

휴대폰은 왼쪽 조이스틱, 오른쪽 공격·회피·물약·상호작용 버튼을 사용합니다.
Q/E/R 기술도 화면 버튼으로 쓸 수 있습니다.
퀘스트 목록과 채팅은 제목 오른쪽 버튼으로 접을 수 있습니다.
메뉴를 열어도 공유 세계의 몬스터는 멈추지 않습니다. 안전한 마을에서 정비하세요.

첫 모험은 마을 중앙 **리아**에게 `숲에서 온 작은 신호` 의뢰를 받고 시작합니다.
북쪽 빛나는 포탈 가까이에서 F를 눌러 숲으로 이동하세요.
슬라임을 처치하고, H 귀환 또는 남쪽 포탈로 돌아와 리아에게 보상을 받습니다.
상인 **모라**, 대장장이 **브란**, 무료 회복을 해주는 **에린**도 마을에 있습니다.

보스는 마지막 타격을 한 한 명에게만 보상을 주지 않습니다.
최근 전투에 직접 기여하고 근처에 살아 있는 플레이어와 조건을 만족하는 파티원이 보상을 받습니다.
채집 자원은 공유 재생 타이머가 있고, 보물 상자는 각 캐릭터가 한 번씩 열 수 있습니다.

## 7. 저장과 재시작: 어디까지 보존되나요?

보존: 계정 ID, 캐릭터 이름/직업, 레벨/경험치, 골드, 인벤토리, 장비/강화,
의뢰/완료 기록, 칭호, 열린 상자, 마지막 위치, 누적 처치 기록, 직업 해금/숙련, 유물/일일/업적 기록, 능력치 배분, 강화 실패 보정, 사망 흔적.

보존하지 않음: 채팅 내역, 현재 파티 구성, 몬스터의 현재 체력/위치, 일반 보스 재생 타이머,
각종 전투 쿨타임, 아직 응답받지 못한 네트워크 요청.
서버가 재시작되면 일반 필드의 몬스터와 자원 상태는 초기화됩니다. 정시 월드 보스는 별도 이벤트 테이블에 상태를 기록하며, 같은 출현 구간 안에서는 마지막 기록부터 복원합니다. 아직 저장하지 못한 피해 기록은 되돌아갈 수 있습니다.

저장은 변경분 30초 주기, 주요 거래·의뢰 등의 지연 병합 저장, 연결 종료,
수동 저장, 정상 종료 시점에 수행합니다.
Supabase 장애나 강제 프로세스 종료 시 **마지막 성공한 저장 이후 진행이 되돌아갈 수 있습니다.**
저장 오류 표시 중에는 성공 상태를 확인하기 전 창을 닫지 않는 편이 좋습니다.
재접속 시 전달되지 않은 공격/거래를 무조건 재전송하지 않도록 했습니다.

**단일 Render 인스턴스만 사용하세요.**
새 버전 배포 전에는 접속자에게 알리고 저장을 마친 뒤 배포하세요.
수평 확장이나 구·신 인스턴스에 동일 계정을 동시에 처리하는 운영은 지원하지 않습니다.
다중 서버 저장 충돌을 해결하는 분산 락/트랜잭션 체계는 구현하지 않았습니다.

## 8. 무료 서비스 제한과 비용 확인

확인 기준: 2026-10-23. 아래 정책은 공급자가 변경할 수 있으므로 배포 전에 공식 페이지를 확인하세요.

- Render 무료 Web Service는 **15분간 수신 트래픽이 없으면 휴면**하며,
  다음 요청 시 기동에 약 1분이 걸릴 수 있습니다. 서비스가 재시작될 수도 있습니다.
- 무료 Web Service의 로컬 파일은 재시작/재배포/휴면 시 보존되지 않습니다.
  그래서 운영 저장을 Supabase에 둡니다.
- 무료 인스턴스 시간·아웃바운드 대역폭·빌드 시간 한도가 있습니다.
  WebSocket 송신도 아웃바운드 사용량에 포함됩니다.
  결제 수단과 지출 제한 설정에 따라 초과 비용 또는 서비스 중단이 발생할 수 있습니다.
- Supabase 무료 플랜에는 DB 500MB와 egress 등 사용량 한도가 있고,
  장기간 비활성 프로젝트가 일시 중지될 수 있습니다.
- 이 게임은 Supabase Realtime을 이동/전투에 사용하지 않습니다.
  전투 트래픽은 Render의 WebSocket, Supabase는 인증·저장 담당입니다.
- 기본 스냅샷 압축은 협상 가능한 클라이언트에서 켜집니다.
  2.0 로컬 24개 연결·6초 테스트의 압축 전송량을 1인 1시간으로 단순 환산하면 약 58.8MiB였으나,
  이것은 실제 Render 청구량이나 장시간 게임 트래픽을 보장하는 수치가 아닙니다.
  초기 그림 다운로드, TLS/TCP 오버헤드, 지역/행동/인원 변화도 고려해야 합니다.

접속자 제한이나 전송 주기를 바꾸려면 `MAX_PLAYERS`, `SNAPSHOT_HZ`를 조정합니다.
전송 주기를 과도하게 낮추면 이동·피격 표시가 늦어집니다.
지속적으로 사람이 많은 게임을 무료 서비스만으로 무제한 운영할 수 있다고 가정하면 안 됩니다.

## 9. 문제가 생겼을 때

| 증상 | 먼저 확인할 것 |
|---|---|
| 첫 접속이 오래 걸림 | Render 무료 서비스의 휴면 복귀, 서비스 로그 |
| 빈 화면 / JS 파일 404 | `npm run build` 성공 여부, `package.json` 위치, Static Site가 아닌 Web Service인지 |
| 저장소 연결 필요 안내 | Supabase URL·공개키·비밀키 3개, 배포 후 재시작 |
| `starfall_characters` 관련 오류 | 올바른 프로젝트 SQL Editor에서 `supabase/setup.sql` 실행 여부 |
| 빠른 시작 실패 | Anonymous Sign-Ins 활성화, 인증 rate limit, 프로젝트 일시 중지 여부 |
| 이메일이 안 옴 | Custom SMTP, 수신 주소 제한, 스팸함, Redirect URL, 이메일 인증 설정 |
| CAPTCHA 오류 | 이 버전에는 CAPTCHA UI 연동 없음. 공개 운영용 통합 구현 필요 |
| 연결되자마자 끊김 | 도메인과 `PUBLIC_ORIGIN`, HTTPS/WSS, 인증 토큰, Render 로그 |
| 다른 기기에서 캐릭터가 없음 | 익명 계정인지, 같은 이메일 계정으로 로그인했는지 |
| 의뢰 완료가 안 됨 | 의뢰 수락 이후의 목표 진행, 리아 근처에서 보고, 선행 의뢰/레벨 |
| 제작 버튼이 비활성 | 요구 레벨, 재료, 골드. 대장장이 근처에서 실행 |
| 저장 재시도 중 | Supabase 상태·한도·키·권한. 성공 상태가 될 때까지 로그 확인 |
| 움직임이 이어짐 | 이동키/조이스틱을 놓고 다시 입력. 입력 만료 시간은 320ms |
| 캐릭터가 다른 창에서 끊김 | 동일 계정은 한 연결만 사용. 다른 계정/시크릿 창으로 테스트 |

## 10. 개발·검증 파일

```text
server/           권한 있는 게임 서버, 인증, REST 저장소, WebSocket
client/           Canvas 렌더러, UI, 입력, 오디오, 인증/접속
shared/           직업·아이템·퀘스트·몬스터·월드와 충돌 규칙
public/           HTML/CSS와 생성된 원본 도트 그림
supabase/         안전한 서버 전용 저장 테이블 SQL
tools/            Pillow 기반 원본 도트 리소스 생성 코드
tests/            규칙/네트워크/저장/브라우저/소규모 부하 테스트
scripts/          빌드와 배포 연결 점검
docs/             구조, 변경 안내, 테스트 기록, 출처/라이선스, 실행 화면
```

```bash
npm test
npm run test:load
```

브라우저 테스트는 선택 사항입니다.
```bash
pip install playwright
playwright install chromium
# 게임 서버를 실행한 별도 터미널에서:
npm run test:browser
```

아트 재생성도 선택 사항입니다.
```bash
pip install Pillow
python tools/generate_art.py
python tools/expand_art.py
python tools/modular_art.py
npm run build
```

3.0에서 실행한 검증 범위와 **실제로 검증하지 못한 항목**은 `docs/TEST_REPORT.md`,
설계와 남은 운영 과제는 `docs/ARCHITECTURE.md`, `SECURITY.md`에 적었습니다.
