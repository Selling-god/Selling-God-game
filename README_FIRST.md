# 판매의 신 / KX CORPORATE V6.2 — EXTREME REALISM

이번 버전의 목표는 '경영을 소재로 한 게임'이 아니라 **회사를 실제로 운영하는 흐름을 게임 안에 압축하는 것**입니다.
CEO 등급, 시즌 점수, 일일 미션 같은 아케이드형 장치는 사용하지 않습니다. 재미는 가격 결정, 제품 실패, 재고, 현금부족, 공급망, 인사, 경쟁사 대응, 인수 실사 같은 경영 의사결정과 그 결과에서 발생합니다.

## 가장 큰 변화

### 1. 프로젝트 = 돈을 돌려주는 상품이 아님
V6.2 이후 신규 R&D/품질/설비/인재/마케팅/복지/준법 프로젝트는 직접 현금을 지급하지 않습니다.
프로젝트 성공/실패가 기술력, 품질, 생산능력, 브랜드, 수요, 조직, 준법 같은 역량에 영향을 주고, 그 효과가 제품 판매와 실제 손익에 연결됩니다.
V6.2 이전 이미 PAYBACK 상태인 프로젝트만 기존 계약으로 잔여 성과금을 계속 지급합니다.

### 2. 실제 제품·서비스 사업
- 신제품 이름/유형/목표가격/개발비/초기 공급능력 결정
- 개발기간 진행
- 개발 완료 후 CEO가 출시 승인
- 판매가격 직접 변경
- 생산능력 증설
- 제품별 마케팅
- 제품 단종
- 실제 판매량, 수요, 생산량, 재고, 단위원가, 매출, 매출총이익률, 불량률, 누적매출 표시

### 3. 공급망과 운전자본
조달 정책을 다음 중 선택합니다.
- 저가 단일조달: 원가 절감 / 품질·공급중단 위험 증가
- 균형 조달
- 프리미엄 공급망: 원가 상승 / 품질·납기 안정
- 이원화 조달: 공급중단 위험 최소화 / 관리비·원가 상승

매출과 현금을 분리했습니다.
- 외상매출금: 매출은 났지만 아직 받지 못한 돈
- 외상매입금: 원가는 발생했지만 아직 공급사에 지급하지 않은 돈
- 재고자산: 생산했지만 아직 판매되지 않은 제품 원가
- 공급사 지급액이 현금을 초과하면 단기 차입금이 증가할 수 있음

### 4. 관리회계
- 제품 매출
- 매출원가
- 매출총이익
- 급여
- 고정 운영비
- R&D·품질 비용
- 마케팅 비용
- 기타 영업비용
- 감가상각
- 영업이익
- 이자·세금
- 순이익
- 영업현금흐름 / 투자현금흐름
- 현금 / 재고 / 외상매출 / 외상매입 / 차입금
- 120 경영주기마다 회계기간 스냅샷 저장

### 5. 거시환경
게임 서버 안의 모든 회사가 같은 환경을 공유합니다.
- 기준금리
- USD/KRW
- 소비경기
- 에너지 원가
- 물류비
- 반도체 사이클

실제 외부 시세를 가져오는 것이 아니라 게임 세계의 거시환경이며, 원가·수요·대출 부담 등에 연결됩니다.

### 6. 경쟁사 경영 AI
BOT 기업은 주가만 랜덤하게 움직이지 않습니다.
- 재고가 쌓이면 가격 인하
- 판매가 공급능력에 근접하면 가격 인상
- 공격형 기업은 가격경쟁 강화
- 기술형 기업은 품질·기술 개선
- 같은 업종 플레이어의 판매가 발생하면 경쟁사가 가격·판매정책으로 대응

### 7. 실제 운영사건과 경영진 결재
다음과 같은 사건이 낮은 빈도로 발생합니다.
- 핵심 공급사 납기 차질
- 품질 이상징후
- 핵심 인력 이탈 위험
- 정보보안 사고 징후
- 규제기관 자료요청

CEO는 전면 대응 / 제한 대응 / 대응 유보 중 하나를 선택합니다.
비용을 줄이면 후속 위험이 커질 수 있고, 결재기한을 넘기면 사건이 자동 악화됩니다.

### 8. M&A 인수 실사
소수지분 매수는 가능하지만 공개매수 전에는 유효한 실사 보고서가 필요하도록 UI를 변경했습니다.
실사에서는 다음이 표시됩니다.
- 인수 위험도
- 예상 시너지
- 실사비
- 보고서 유효기간

실사비는 대상기업 규모에 따라 법인현금에서 실제 지출됩니다.

## 설치

### 기존 V6.1.2 사용 중인 경우
1. 이 프로젝트의 `app.js` / `styles.css` 또는 `public/app.js` / `public/styles.css`를 교체합니다.
2. Supabase SQL Editor에서 `RUN_THIS_IN_SUPABASE_V6.2.sql` 전체를 **한 번만** 실행합니다.
3. Render/GitHub를 재배포합니다.
4. 브라우저에서 강력 새로고침(Ctrl+Shift+R)을 합니다.

### 기본 회사 API가 없는 새 DB인 경우
V6.2는 V6.1.2 위에 올라가는 현실경영 확장판입니다. 먼저 V6.1.2의 기본 회사 SQL을 적용해 `kx_company_api_v1`을 만든 뒤 V6.2 SQL을 실행합니다.

## 데이터 보존
V6.2 SQL은 기존 유저, 회사, 주식, 은행, 지분, M&A, 뉴스 데이터를 삭제하지 않습니다. 새 테이블/필드/트리거/RPC를 추가하거나 교체합니다.
