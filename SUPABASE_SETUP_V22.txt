RIFT DECK v2.2 - 로그인 + 클라우드 기록 저장 설정 (기존 Supabase 그대로 사용)

딱 3단계입니다.

1) Supabase -> SQL Editor에서 이 파일을 한 번 실행
   supabase/RUN_THIS_IN_SUPABASE_RIFT_V22.sql

2) Render -> RIFT DECK Web Service -> Environment에 아래 2개를 추가
   SUPABASE_URL = 기존 Supabase Project URL
   SUPABASE_SECRET_KEY = Supabase의 Secret key (sb_secret_...)

   만약 기존 프로젝트에서 Secret key 대신 예전 service_role key를 쓰고 있다면
   SUPABASE_SECRET_KEY 대신 아래 이름으로 넣어도 됩니다.
   SUPABASE_SERVICE_ROLE_KEY = 기존 service_role key

   선택 사항:
   SUPABASE_PUBLISHABLE_KEY = sb_publishable_...
   또는 구형 SUPABASE_ANON_KEY
   없어도 서버 측 로그인 프록시는 동작하도록 만들었습니다.

3) Save Changes -> Render가 재배포되면 끝
   https://게임주소/healthz 에서 auth가 "supabase"면 정상입니다.

저장되는 것
- 계정 / 닉네임
- 카드 컬렉션 / 시작 덱
- 프리즘 / 잔광 / 봉인구
- 가챠 전설·신화 천장
- 던전/여행 횟수, 난이도별 최고층·클리어 기록
- 최근 원정 기록
- 진행 중인 방/전투 스냅샷(서버 재시작 후 복구용)

보안
- 비밀번호는 RIFT DB에 저장하지 않습니다. Supabase Auth가 관리합니다.
- Secret/service_role 키는 Render Environment에만 넣으세요.
- Secret/service_role 키를 public/app.js, index.html 또는 GitHub 코드에 직접 적지 마세요.
- 기존 kx_* 테이블은 이 SQL이 수정하거나 삭제하지 않습니다.

게임 로그인 규칙
- 아이디: 영문 소문자 / 숫자 / _ 조합 3~20자
- 비밀번호: 6~72자
- 닉네임: 최대 14자
- 게스트로 먼저 플레이했다면 같은 브라우저에서 계정 생성/로그인 시 게스트 진행도를 계정으로 승계합니다.
