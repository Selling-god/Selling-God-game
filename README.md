# RIFT DECK : ABYSS EXPEDITION v2.1.0

브라우저에서 실행되는 **동적 서버 기반 카드 로그라이트 + 1~4인 협동 50층 던전**입니다.

기존 Selling-God 경제게임 코드를 덧붙인 버전이 아니라, 카드 수집/런 성장/협동 던전을 중심으로 게임 루프를 다시 설계했습니다. PokeRogue에서 느낄 수 있는 빠른 반복 런, 전투 뒤 선택형 보상, 희귀 수집의 긴장감 같은 장르적 아이디어를 참고했지만 Pokemon/PokeRogue의 캐릭터, 스프라이트, 로고, 이름, UI 자산을 복제하지 않습니다. 전투는 손패, 에너지, 방어, 적 의도, 상태이상, 드로우/버림 더미를 사용하는 덱빌딩 방식입니다.

## 이번 v2에서 달라진 핵심

- Render의 `Missing script: "build"` 오류 수정: 실제 `npm run build` 스크립트와 빌드 검증기를 추가했습니다.
- 던전을 **50층**으로 확장했습니다.
- 던전 난이도를 **보통 / 어려움 / 지옥** 3단계로 추가했습니다.
- **모든 층 완료 후 개인 보상 선택**: 각 플레이어가 랜덤 카드 또는 런에 도움 되는 아이템 중 1개를 고릅니다.
- 기본 보상은 카드 3개 + 아이템 2개 형태의 5개 후보이며, 일부 아이템 효과로 선택지가 늘어날 수 있습니다.
- 런 골드를 사용해 보상 후보를 재굴림할 수 있습니다. 최대 5회이며 비용은 점차 증가합니다.
- 카드 수를 기존 63종의 정확히 5배인 **315종**으로 확장했습니다.
- 런 아이템 **48종**, 일반 적 **50종**, 보스 **5종**, 바이옴 **5종**을 포함합니다.
- 315장 모두 고유 ID/이름/수치/효과 데이터를 가지며 각각 대응하는 오리지널 카드 PNG가 있습니다.
- 50층은 10층 단위 5개 구역으로 진행되고, 10/20/30/40/50층에 보스가 등장합니다.
- 1~4인 협동 방, 서버 권한 전투, SSE 실시간 동기화, 경로 투표를 유지/확장했습니다.

## 바로 실행

Node.js 20~26을 권장합니다. Render 설정은 Node 22로 고정되어 있습니다.

```bash
npm ci
npm run build
npm start
```

브라우저에서 `http://localhost:3000`을 엽니다.

전체 검증:

```bash
npm run check
npm test
```

`npm test`는 빌드 검증, 기본 API, 4인 협동, 실제 카드 전투, 50층 완주 테스트를 차례로 실행합니다.

## 50층 협동 던전

메인 콘텐츠입니다. 최대 4명이 각자 시작 덱을 들고 같은 방에 입장합니다.

### 난이도

- **보통**: 표준 적 체력/공격력, 표준 보상 확률
- **어려움**: 적 체력과 공격력이 증가하는 대신 상위 보상 가중치와 획득 재화가 증가
- **지옥**: 가장 높은 적 스케일과 공격 패턴 압박. 대신 상위 등급 보상 가중치와 클리어 보너스가 가장 큼

### 층 구조

- 1~10층: 첫 번째 구역
- 11~20층: 두 번째 구역
- 21~30층: 세 번째 구역
- 31~40층: 네 번째 구역
- 41~50층: 최종 구역
- 5층 단위: 정예 위험 구간
- 10/20/30/40/50층: 지역 보스
- 50층 보스 보상 확정 후 해당 난이도 클리어 기록과 최종 재화 보너스 지급

### 매 층 보상

전투뿐 아니라 사건, 야영지, 보물, 상점 같은 층도 처리가 끝나면 **무료 보상 선택 단계**로 이어집니다. 각 플레이어에게 후보가 따로 생성되므로 4명이 같은 카드를 억지로 나눠 가질 필요가 없습니다.

기본적으로 랜덤 카드와 런 아이템이 섞인 후보 중 하나를 선택합니다. 카드 선택 시 영구 컬렉션에 등록되고 현재 런 덱에도 들어갑니다. 아이템은 해당 런 동안 스택형 패시브로 작동합니다.

아이템 예시는 최대 HP, 시작 에너지, 시작 방어, 추가 드로우, 카드/유닛/스펠 피해 강화, 피해 감소, 회복, 보상 등급 가중치, 재굴림 할인, 보스 추가 피해, 부활 등의 계열을 포함합니다.

## 일반 여행

일반 여행은 컬렉션 확장을 위한 장기 반복 모드입니다.

- 전투와 보상을 반복하며 덱을 성장
- 일정 확률로 카드 흔적 발생
- 기본/은빛/왕가 봉인구로 카드를 봉인해 영구 컬렉션에 획득
- 전설/신화는 일반 여행에서 출현 확률 자체가 매우 낮고 봉인 성공률도 낮음
- 획득 카드는 다음 런의 시작 덱 후보로 사용 가능

## 전투

- 플레이어별 HP/손패/에너지/드로우 더미/버림 더미 독립
- 유닛 카드: 최대 3칸 소환, 팀 턴 종료 후 자동 공격 및 고유 훅 발동
- 스펠 카드: 즉시 피해, 광역, 방어, 회복, 드로우, 약화, 취약, 화상, 감전, 행동 봉인 등
- 적은 다음 행동(Intent)을 미리 표시
- 4인 협동에서는 각자 행동 후 전원이 턴 종료하면 유닛 공격 → 적 행동 → 다음 턴을 서버가 계산
- 클라이언트가 데미지/드롭 결과를 임의로 정하지 못하도록 서버가 권한을 가짐

## Render 배포

가장 안전한 방법은 저장소 루트에 이 프로젝트의 파일이 바로 보이도록 업로드한 뒤 `render.yaml`을 사용하는 것입니다.

수동 Web Service 설정을 쓴다면:

```text
Build Command: npm ci && npm run build
Start Command: npm start
Node Version: 22
Health Check Path: /healthz
```

이전 화면에서 발생한 `npm error Missing script: "build"`는 v2의 `package.json`에 `build` 스크립트가 있으므로 더 이상 발생하지 않아야 합니다. 자세한 확인 절차는 `RENDER_DEPLOY.md`를 보세요.

## 데이터 저장에 대한 중요한 점

현재 프로필/컬렉션/재화는 `data/profiles.json` 어댑터를 사용합니다. 로컬 실행과 한 인스턴스 테스트에는 충분하지만 **Render의 임시 로컬 디스크를 영구 계정 DB로 간주하면 안 됩니다.** 공개 서비스 단계에서는 Supabase/Postgres 같은 영구 DB와 Auth로 교체해야 재배포/재시작 후에도 계정 데이터가 안전하게 유지됩니다.

## 저작권/브랜딩

이 프로젝트는 장르와 플레이 루프를 참고하되 Pokemon/PokeRogue의 실제 그래픽, 캐릭터, 스프라이트, 로고, 명칭을 포함하지 않습니다. RIFT DECK의 카드, 적, 바이옴, 아이템과 제공된 절차형 픽셀 자산은 프로젝트 전용 독자 자산입니다.

## v2.1 배포 식별과 기존 Supabase

v2.1의 배포 식별자는 `RIFT-V2.1-20260910`입니다. `/healthz`에서 이 값을 확인할 수 있습니다.

기존 Supabase 프로젝트를 버릴 필요는 없습니다. 기존 `kx_*` 데이터는 그대로 두고 `supabase/RUN_THIS_IN_SUPABASE_RIFT_V21.sql`을 한 번 실행해 `rift_profiles` 테이블만 추가합니다. Render에는 서버 전용 `SUPABASE_SERVICE_ROLE_KEY`를 등록합니다. 브라우저 코드에는 service-role 키를 넣지 않습니다.
