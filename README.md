# RIFT DECK : ABYSS EXPEDITION

브라우저에서 바로 실행되는 **동적 서버 기반 카드 로그라이트 + 최대 4인 협동 던전** 1차 완성본입니다.

이 프로젝트는 기존 `Selling-God` 게임의 경제 시스템을 이어 붙인 패치가 아니라, 요청에 맞춰 **게임 구조를 새로 만든 전체 교체본**입니다. PokeRogue의 빠른 반복 플레이, 스타터/수집, 희귀 개체의 긴장감, 전투 후 보상 선택 같은 로그라이트 UX를 참고했지만, 포켓몬/포켓로그의 이름·이미지·스프라이트·UI 자산을 복제하지 않습니다. 전투는 카드 손패·에너지·방어·적 의도 표시·상태이상·덱 순환을 사용하는 덱빌딩 방식입니다.

## 바로 실행

Node.js 18 이상에서:

```bash
npm install
npm start
```

브라우저에서 `http://localhost:3000`을 엽니다.

테스트:

```bash
npm test
```

## 구현된 핵심 시스템

- **동적 Node 서버**: 단순 정적 호스팅이 아니라 방, 전투, 보상, 포획 판정을 서버가 관리합니다.
- **SSE 실시간 동기화**: 협동 방의 참가/경로 투표/전투/보상 상태가 접속자에게 즉시 전파됩니다.
- **1~4인 협동 던전**: 30층 클리어 구조, 5층 단위 위험 증가, 10/20/30층 보스, 30층 최종 클리어 보너스.
- **일반 여행**: 전투 후 일정 확률로 야생 카드 흔적이 등장하며 기본/은빛/왕가 봉인구로 포획합니다.
- **희귀도**: 일반 / 희귀 / 초희귀 / 전설 / 신화. 전설·신화는 일반 여행에서 극단적으로 낮은 출현 가중치와 낮은 봉인 성공률을 가집니다.
- **유닛/스펠 카드**: 유닛은 3개 슬롯에 소환되어 팀 턴 종료 후 공격하고, 스펠은 즉시 효과를 냅니다.
- **덱빌딩 전투**: 3 에너지, 5장 드로우, 드로우/버림 덱 순환, 방어, 약화, 취약, 화상, 감전, 행동 봉인, 적 의도 표시.
- **협동 전투**: 플레이어별 HP/손패/에너지는 독립. 전원이 턴 종료하면 유닛 공격 → 적 행동 → 다음 턴 순서로 서버가 처리합니다.
- **경로 선택**: 전투 / 정예 / 보스 / 야영지 / 보물 / 사건 / 유랑 상점. 협동에서는 전원 투표 후 최다 득표 경로로 진행합니다.
- **카드 영구 수집**: 여행 포획, 전투 보상, 상점, 사건, 가챠에서 얻은 카드가 컬렉션에 저장됩니다.
- **복각 가챠**: 현재 픽업 배너, 1회/10회, 등급 확률, 전설/신화 천장, 픽업 55%, 중복 잔광 환급.
- **덱 편성**: 보유 카드 8~16종을 시작 덱으로 저장. 전투 시 최소 12장으로 순환 확장.
- **유물**: 휴식 강화, 봉인 확률, 최대 에너지, 보스 공격력 등 런 내 보조 효과.
- **반응형 UI**: PC/태블릿/휴대폰에 맞춰 카드 손패가 가로 스크롤되고 전투 UI가 축소됩니다.
- **오리지널 픽셀 그래픽**: 외부 게임 이미지를 가져오지 않고 Canvas에서 카드/몬스터/배경을 절차적으로 그립니다.
- **WebAudio 효과음**: 별도 음원 파일 없이 카드 사용/피격/승리/소환의 짧은 효과음을 합성합니다.

## 모드 설계

### 1. 일반 여행

컬렉션 확장이 목적입니다. 전투 보상으로 카드를 받는 것 외에도 야생 카드 흔적이 발생합니다. 높은 등급일수록 흔적 자체가 매우 드물며, 봉인 성공률도 낮습니다. 획득한 카드는 현재 여행 덱에도 들어가고 다음 런의 시작 덱 후보가 됩니다.

### 2. 협동 던전

메인 콘텐츠입니다. 최대 4명이 각자 시작 덱을 들고 동일한 방에 입장합니다. 경로를 함께 정하고, 전투에서는 각자 자신의 카드와 에너지를 사용합니다. 전원이 행동을 마치면 서버가 유닛 공격과 적 턴을 한꺼번에 계산합니다. 30층 최종 보스를 쓰러뜨리고 보상을 확정하면 던전 클리어가 기록됩니다.

## 서버 구조

`server.js` 하나가 정적 파일 제공 + API + 멀티플레이 룸 + 전투 엔진을 맡습니다. 별도 프레임워크/패키지가 필요하지 않아 Render에서 그대로 실행할 수 있습니다.

주요 API:

- `GET /healthz`
- `GET /api/meta`
- `POST /api/profile`
- `POST /api/deck`
- `POST /api/gacha/pull`
- `GET /api/rooms`
- `POST /api/rooms/create`
- `POST /api/rooms/join`
- `GET /api/room/:code`
- `GET /api/room/:code/stream?profileId=...`
- `POST /api/room/:code/start`
- `POST /api/room/:code/vote`
- `POST /api/room/:code/play`
- `POST /api/room/:code/end-turn`
- `POST /api/room/:code/event`
- `POST /api/room/:code/reward`
- `POST /api/room/:code/buy`
- `POST /api/room/:code/capture`
- `POST /api/room/:code/continue`

## Render 배포

이 폴더를 GitHub 저장소 루트에 올린 뒤 Render에서 Blueprint 또는 Web Service로 연결하면 `render.yaml`의 설정을 사용할 수 있습니다.

현재 프로필은 `data/profiles.json`에 기록됩니다. **Render 무료 인스턴스의 로컬 파일은 영구 데이터베이스로 보면 안 됩니다.** 실제 공개 서비스에서 계정/컬렉션을 재배포 후에도 유지하려면 Supabase/Postgres 어댑터로 바꾸는 것이 다음 단계입니다. 반면 멀티플레이 방과 전투가 동적 서버에서 처리되는 구조 자체는 이미 구현되어 있습니다.

## 중요한 저작권/브랜딩 메모

PokeRogue/Pokemon의 이미지·스프라이트·명칭·로고를 프로젝트에 포함하지 않았습니다. 공개 배포 가능한 독자 게임으로 확장하기 위한 의도입니다. 현재 `RIFT DECK`, 카드, 몬스터, 바이옴 및 절차형 픽셀 아트는 이 프로젝트용 오리지널입니다.
