# 콘텐츠를 수정하는 곳

## 게임 이름과 첫 화면
`public/index.html`, `public/style.css`를 수정합니다.
첫 화면의 도트 배경은 `public/assets/title.png`입니다.
화면에 쓰는 글꼴은 운영체제 글꼴이며 별도 폰트 파일을 배포하지 않습니다.

## 직업·레벨·아이템·퀘스트
`shared/content.js`에 데이터가 모여 있습니다.
CLASSES / ITEMS / RECIPES / MONSTERS / QUESTS / ZONES / NPCS를 확인하세요.
스킬에 새로운 행동을 넣을 때는 데이터만이 아니라 `server/game.js`의 판정과
`client/render.js`의 이펙트를 함께 수정해야 합니다.

아이템 id를 바꾸거나 삭제하면 기존 저장의 참조가 깨집니다.
사용 중인 id는 유지하고 새 id를 추가하세요.
현재 강화는 개별 아이템 인스턴스가 아니라 동일 아이템 id의 강화 단계를 공유합니다.

퀘스트 objective의 kind는 kill 또는 gather, kill target='any'는 모든 몬스터입니다.
킬·채집은 수락 이후부터 기록합니다. gathered 재료를 먼저 써도 완료 기록이 사라지지 않습니다.
새 quest id와 선행 requires를 만들고 순환 의존성이 없는지 확인하세요.

## 맵과 충돌
`shared/world.js`의 시드, 포탈, 보스 위치, 장식 배치, 생성 규칙을 수정합니다.
클라이언트와 서버에 동일하게 배포되어야 합니다.
그림 크기와 충돌 칸은 별개입니다. 큰 건물을 추가하면 footprint도 조정하세요.
`npm test`의 지도 도달성 검사를 함께 돌리는 것이 좋습니다.

## 도트 그림
`tools/generate_art.py`는 원본 도트 그림 생성 소스입니다.
Pillow로 도형과 픽셀을 직접 그리며, 스크린샷/영상의 캐릭터를 추출하지 않습니다.
atlas.json은 atlas.png 안의 프레임 좌표·크기·바닥 기준점 정보를 갖습니다.
자신이 권리를 가진 전문 스프라이트로 교체할 때는 같은 프레임 id/앵커를 맞추거나
렌더러의 frame 선택 규칙을 함께 변경하세요.

## 서버 규칙
피해량, 스킬 비용, 몬스터 AI, 보상, 제작/판매/파티 등의 최종 판정은 `server/game.js`입니다.
`client/main.js`에 보상을 추가하는 것만으로는 서버의 실제 캐릭터가 바뀌지 않습니다.
새 요청 종류에는 반드시 소유권·수량·거리·쿨타임 검사를 넣으세요.

## 검증과 배포
코드 수정 → npm test → npm run build → 로컬 두 브라우저 테스트 → 저장/재접속 확인 → 배포 순서가 좋습니다.
새 버전 배포 전 접속자에게 알리고 저장을 확인하세요.
현재 프로토콜 버전 자동 강제 갱신 기능은 없으므로 배포 후 새로고침을 안내하세요.
